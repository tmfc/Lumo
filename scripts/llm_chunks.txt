6.2.推送服务
6.2.1. 完整性校验
回调接口使用签名校验数据完整性，由硅基提供第三方appId及sign_secret，在请求头
信息中增加相关信息进行数据完整性校验。
请求头增加如下字段：
序号 名称 类型 必须 默认值 描述
1 appId string 是 /
由硅基提供（若无特殊设定，值等于
appKey）
2 nonce string 是 / 10位字母+数字随机值，保证每次不同
3 signature-app string 是 / 由如下签名算法得出
签名算法如下：
String bt1 = appId + nonce
String bt2 = 请求体内容（JSON格式的字符串）
String bt3 = 签名秘钥（sign_secret）
String signature-app = MD5（bt1 + bt2 + bt3）
推送数据处理逻辑说明：
1、数据存在重复推送的情景故所有推送数据需接入方自行解决幂等性问题。用户授权时会
出现相关订阅事件的数据推送，包括但不限于(新增设备信息(20901)、设备信息更新推送
(20902)、报告信息(20904)、全量血糖数据(20903) ）。
2、不同回调类型不保证顺序性，需接入方自行实现数据关联。例如设备新增，血糖数据，
报告数据三个事件推送·时间不分前后。
3、每次授权成功（包括取消后重新授权）时会推送激活有效期内的设备信息包括：新增设
备信息(20901)、设备信息更新推送(20902)、报告信息(20904)及血糖数据(20903)，其中
20903事件推送数据为该设备激活至授权成功期间内全量的血糖数据，且在每次重新授权时
都会进行推送。
6.2.2.Callback
描述：
实时回调，包括201:实时推送授权业务ID。机构方接收到推送请求后，只有在规定时间内返回
字符串“SUCCESS”才表示推送成功，否则硅基认为推送失败，硅基会提供7次重试机会，若7
次都推送都不成功，则不再进行尝试推送。这7次推送的时机分别是：30s 2min 10min 1h
2h 6h 1day。若发生重推，需要机构方自行保证接口的幂等性。
